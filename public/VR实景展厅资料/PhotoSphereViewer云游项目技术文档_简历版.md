## 1. 项目概述

**搏鲨 VR 实景展厅**是一个面向服装制造企业的数字化展厅系统，通过 **360° 全景实景拍摄 + Web 3D 渲染技术**，将真实的服装工厂（厂区入口、办公楼、生产车间、展厅、办公室等 **19 个实景场景**）完整"搬"进手机浏览器，实现：

- **全景漫游**：用户在浏览器中 360° 自由旋转视角，任意缩放，沉浸式参观工厂；
- **跨场景导览**：通过场景间热区箭头一键切换，形成"厂区大门 → 车间 → 展厅 → 办公室"的完整导览动线；
- **产品展示**：在展厅场景的货架/展位位置挂载 **42 个服装 SKU 热点**，点击即可查看该产品的实拍图集（每款 8~18 张细节图）；
- **多端适配**：手机/平板/PC 浏览器直接打开即用，支持手机陀螺仪随动视角与 VR 双屏立体模式。

**核心亮点**：整套系统**无需服务器部署、无需租用域名空间、无需任何商业软件授权**，一次开发、终生使用，浏览器打开即可运行，可自由嵌入官网、朋友圈、抖音等任意渠道传播。

## 2. 项目背景与价值

### 2.1 业务背景

服装制造企业普遍面临以下痛点：

| 痛点 | 传统解决方案 | 本项目方案 |
|---|---|---|
| 客户验厂/看厂成本高 | 客户亲临工厂，耗时耗钱 | 手机看全景实景，远程云参观 |
| 产品款式多、展示方式单一 | 静态图片册、样衣寄送 | 场景内嵌产品热点，点开即看细节图集 |
| 缺少可传播的数字化名片 | 无 | 一个链接全网传播（官网/朋友圈/短视频） |

### 2.2 技术价值

- 验证了 **WebGL 全景渲染 + 图结构场景漫游** 在传统制造业展示场景的落地可行性；
- 沉淀了一套"**数据采集 → 数据处理 → 资源本地化 → 前端组装**"的完整数据工程管线；
- 实现了 **100% 前端静态化**交付，摆脱了对服务器、数据库、第三方商业 SDK 的依赖，部署成本趋近于零。

### 2.3 商业价值

- 帮助企业以极低成本获得"数字展厅"能力，提升品牌形象与客户信任；
- 缩短客户决策链路：云看厂 → 云选款 → 在线询单；
- 项目模式可复制（复制数据与配置即可为任意工厂快速搭建同类展厅）。

```
│  WebGL 渲染 · 纹理映射 · 摄像机控制                        │
├──────────────────────────────────────────────────────────┤
│  资源层（静态资产）                                       │

└──────────────────────────────────────────────────────────┘
```

### 3.2 运行时架构特点

- **零后端**：无服务器、无数据库、无 API，运行时仅需静态文件托管（甚至可直接 `file://` 或任意静态服务器打开）；
- **原生 ESM**：通过 `<script type="importmap">` 映射模块，浏览器原生加载 CDN 上的 ES Module，无打包器、无构建步骤；
- **插件式扩展**：业务功能全部以"监听事件 + 调用插件 API"的方式挂载在开源核心之上，与开源库完全解耦，便于升级维护；
- **数据与代码分离**：场景图、产品映射、热点坐标等数据全部集中在配置区（`nodes` / `PRODUCT_DATA`），新增一个场景/产品只需增改配置。

### 3.3 数据流（开发期）

```
720云全景平台(公网数据)
   │  DrissionPage 浏览器自动化抓取 tour_config.json
   ▼
场景/热点配置提取 ──► data/hotspots_extracted.json（场景ID、热点、ath/atv 角度）
产品热点提取    ──► data/product_map.json（产品→角度+图片清单）
媒体链接清单    ──► product_urls_final.json → download_list.json
   │  批量下载（全景 6 面图 / 场景缩略图 / 产品图）
   ▼
assets/ 本地资源目录
   │  手工整理 + 角度换算（度→弧度）+ 组装节点图
   ▼
js/app.js 场景节点图 + 产品热点配置（最终运行数据）
```

### 4.2 选型理由

1. **选 Photo Sphere Viewer 而非自研**：全景查看器涉及大量 3D 数学（球面投影、摄像机插值、纹理采样），成熟开源库 + MIT 许可可商用，且其**适配器模式**支持 cubemap / equirectangular / EAC 等多种全景格式，扩展性强；
2. **选 CubemapAdapter 而非等距柱状图**：源平台数据本身为 6 面立方体格式，直接适配，且立方体贴图在纹理采样上**失真更小、细节更清晰**；
3. **选原生 ESM + importmap 而非 webpack/vite**：项目为纯静态交付，无需构建产物，CDN 直出 + 本地 `lib/` 副本双通道，兼顾线上速度与离线部署；
4. **选 DrissionPage 采集**：浏览器自动化方案可直接解析动态渲染页面，稳定拿到全景平台的场景配置与媒体资源真实链接。

## 5. 核心技术原理

### 5.1 全景渲染原理（照片级 3D，非建模）

本项目**不是三维建模**，而是"照片投影"方案：

1. 每个场景由全景拍摄设备输出 **6 张方形面图**（左/前/右/后/上/下，`mobile_l/f/r/b/u/d.jpg`）；
2. 通过 `cubemap(sceneDir)` 将 6 图组装为 `{left, front, right, back, top, bottom}` 纹理对象；
3. three.js 在 WebGL 场景中构建**内表面贴图的立方体（skybox）**，摄像机置于中心；
4. 用户拖拽/陀螺仪旋转时，实际上是摄像机 **yaw（水平方位角）/ pitch（垂直俯仰角）** 在变化，配合 zoom 实现缩放；

> 关键认知：这是用 6 张照片"骗过"人眼形成 3D 沉浸感，成本远低于三维建模，且真实感极强，非常适合厂房/展厅类实景展示。

### 5.2 虚拟导览：场景节点图（Graph）

- 19 个场景定义为 19 个 **node**（含 `panorama` 六面图、`thumbnail` 缩略图、`caption` 标题）；
- 每个 node 的 `links` 声明可跳转的邻居节点及**箭头锚点位置**（yaw/pitch），构成一张**有向图**：
  - 例：`01 厂区入口 → 02 办公楼入口 → 03 办公楼大厅 → … → 19 厂区俯瞰`
  - 节点间可双向回跳（如 05 休闲裤2区 ↔ 04/06），形成灵活动线；
- 点击箭头 → `virtualTour.setCurrentNode(nodeId)` → 插件内部执行场景切换（纹理替换 + 过渡动画）。

### 5.3 球面坐标系统与角度换算

- 全景空间采用 **球面坐标**：`yaw`（方位角，弧度）与 `pitch`（俯仰角，弧度），值域 yaw ∈ [-π, π]、pitch ∈ [-π/2, π/2]；
- 热点/箭头/初始视角全部用 yaw/pitch 精确定位；
- 源平台数据为**角度制**（ath/atv，单位度），落地时统一换算为弧度（`deg × π / 180`），保证跨数据源的一致性；
- `panoData: { poseHeading: 0 }` 校正场景朝向，确保各场景方位基准统一。

### 5.4 产品热点与详情展示

- `mkMarker()` 生成 **HTML 标记**（渐变胶囊按钮 + 悬浮 tooltip），通过 markers-plugin 锚定到球面指定坐标，随视角缩放自动适应屏幕；
- 产品数据采用 **SKU 映射表** `PRODUCT_DATA`：`{货号 → {标题, 图片目录, 图片数量, 特殊扩展名}}`，动态生成图片 URL 序列 `assets/products/<货号>/1.jpg … N.jpg`；
- 点击产品热点 → 自研 **DOM 弹窗**（主图 + 缩略图条 + 点击切换 + ESC/遮罩关闭），不依赖 UI 框架；
- 无人机图标热点 → 一键跳转"厂区俯瞰"航拍场景，形成"地面 + 空中"双视角体验。

### 5.5 移动端与 VR 体验

- **GyroscopePlugin**：调用 DeviceOrientation 传感器，手机转动即视角转动（"转头看"体验）；
- **StereoPlugin**：渲染左右双视口，配合 Cardboard/VR 眼镜实现立体沉浸；
- **AutorotatePlugin**：空闲 5s 自动以 1rpm 巡航旋转，营造"自动参观"效果；
- navbar 提供 zoom / move / gallery / markers / gyroscope / stereo / fullscreen 全套交互入口。

## 6. 数据工程与资源管线

### 6.1 数据采集（公网真实数据）

- 使用 **DrissionPage**（Python 浏览器自动化库）访问目标全景平台，动态渲染页面抓取 `tour_config.json`；
- 提取内容：场景列表（sceneId、名称、路径、materialId）、场景跳转热点（ath/atv、目标场景）、产品热点（标题、角度、图片链接）；
- 留存分析脚本 `analyze_bs9987.py` 用于定向核查指定 SKU（如 BS-J9987）的配置详情。

### 6.2 数据加工

| 产物 | 内容 | 用途 |
|---|---|---|
| `data/hotspots_extracted.json` | 19 场景的跳转热点 + 产品热点原始配置 | 生成场景链接与坐标 |
| `data/product_map.json` | 产品 → 球面坐标 + 图片完整清单 | 生成 PRODUCT_DATA 与图片引用 |
| `product_urls_final.json` | 全量媒体 URL 清单（产品图/全景图） | 生成下载任务 |
| `download_list.json` | 分批下载任务（URL → 本地路径映射） | 资源本地化 |

### 6.3 资源本地化

- 按 `download_list.json` 批量下载全景 6 面图（19 场景 × 6）、场景缩略图（19 张）、产品图（42 SKU × 8~18 张）至 `assets/`；
- `need_download.json` / `still_need.json` 用于下载任务去重与断点续传跟踪；
- 资源落地后，**运行时与源平台完全解耦**，不再依赖任何外部媒体服务。

### 6.4 最终组装

将加工后的数据手工收敛为运行配置（`nodes` 节点图、`galleryItems` 相册、`PRODUCT_DATA` 产品表），完成"采集 → 加工 → 落地 → 组装"全链路闭环。

## 7. 关键技术难点与解决方案

### 7.1 难点一：Gallery 插件缩略图渲染异常

**问题**：PSV Gallery 插件在缩略图资源加载异常时会渲染 SVG 占位图，场景相册无法正常显示真实封面。

**方案**：
- 自研 `fixGalleryThumbnails()`：监听 DOM 变化（`MutationObserver`），检测到 `.psv-gallery-item` 后注入真实 `<img>` 封面，并隐藏 SVG 占位；
- 双保险：以 `setInterval(3s)` 周期性兜底扫描，确保插件异步渲染后依然能补齐；
- **价值**：不修改开源库源码，纯外部修补，保证升级兼容性。

### 7.2 难点二：热点点击与视角拖拽的冲突

**问题**：点击产品/无人机热点时，鼠标按下与抬起之间的位移会被识别为"拖拽旋转视角"，导致 `select-marker` 事件不稳定，点击失效。

**方案**：
- 在容器上以捕获阶段监听 `mousedown` / `mouseup`，记录目标热点 ID；
- 抬起时校验目标仍是该热点（排除拖拽误触），延迟 80ms 执行跳转/弹窗；
- **价值**：双通道事件兜底（插件事件 + 原生事件），将点击命中率提升到稳定可用的程度。

### 7.3 难点三：多数据源角度单位不一致

**问题**：源平台热点坐标为角度制（ath/atv），PSV 渲染坐标要求弧度制（yaw/pitch），且 `pitch` 方向定义存在符号差异，直接套用会错位。

**方案**：
- 建立统一的坐标换算约定：`rad = deg × π / 180`，明确 ath→yaw、atv→pitch 的映射关系；
- 以 `panoData.poseHeading` 统一各场景朝向基准；
- 每个热点坐标逐一对照全景画面人工校准，保证热点与实际货架位置对齐。

### 7.4 难点四：场景切换后的视角姿态问题

**问题**：切换场景后，上一场景遗留的俯仰角（pitch）会导致新场景"歪着头"进入，影响体验。

**方案**：
- 监听 `node-changed` 事件，切换完成后延迟 150ms 将 pitch 归零（仅保留 yaw），保证每次进入新场景视角水平；
- 同步更新 `document.title` 与场景标题，提升导航反馈。

### 7.5 难点五：资源本地化与断点续传

**问题**：全景图、产品图合计上千张，源媒体 URL 分散，一次性下载易中断、易重复。

**方案**：
- 生成 URL→本地路径映射清单（`product_urls_final.json` / `download_list.json`），按批次执行；
- 用 `need_download.json` / `still_need.json` 跟踪剩余任务，实现去重与断点续传；
- 完成后运行时零外部媒体依赖，彻底解耦源平台。

## 8. 性能与部署方案

### 8.1 性能优化

| 手段 | 说明 |
|---|---|
| 静态资源直出 | 全景图/产品图均为静态文件，浏览器缓存友好，二次访问秒开 |
| 懒加载纹理 | 场景切换时才加载目标场景六面图，首屏仅加载当前场景 |
| CDN 分发 | 开源库走 jsDelivr CDN，全球节点加速，本地仅承载业务资源 |
| 本地副本 | `lib/` 内 vendored 开源包，支持内网/离线环境无网部署 |
| 资源瘦身 | 缩略图独立小图（`assets/scenes/*.png`），避免相册加载全景大图 |

### 8.2 部署方案（三选一，均免服务器）

| 方式 | 说明 | 适用场景 |
|---|---|---|
| 本地静态服务器 | `npx serve . -p 8080` | 开发调试 |
| 任意静态托管 | 直接托管到官网/OSS/对象存储 | 生产公网 |
| 离线/内网 | `file://` 或内网共享，配合 `lib/` 本地副本 | 展会、内网环境 |

> 亮点：**无需服务器部署、无需额外软件授权、一次开发、终生使用**，且可自由嵌入官网、朋友圈、短视频平台传播。

## 9. 项目亮点总结

1. **零成本交付**：纯前端静态化，无后端、无数据库、无商业 SDK，一次开发永久使用；
2. **照片级真实感**：全景实拍 + 立方体贴图，真实感远超三维建模，成本却低一个量级；
3. **完整的工程管线**：从公网数据采集（DrissionPage 自动化）到资源本地化、坐标换算、前端组装，全链路自主可控；
4. **插件化架构**：业务层与开源核心解耦，8 大功能插件按需装配，可维护、可升级、可扩展；
5. **多端沉浸体验**：手机陀螺仪、VR 双屏、自动巡航、全屏展示，兼顾移动端与桌面端；
6. **数据驱动可复制**：新增场景/产品只需增改配置，可快速为其他工厂复制同类展厅；
7. **工程细节扎实**：针对插件缩略图异常、点击冲突、角度错位、视角姿态等真实问题逐一修复，体现了攻坚能力。
