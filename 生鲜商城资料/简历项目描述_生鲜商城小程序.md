## 生鲜商城小程序系统 | 全栈工程师（独立开发）

**项目周期**：2026.08　**项目角色**：全栈独立开发（需求 → 设计 → 三端编码 → 部署文档）
**技术栈**：Spring Boot 3.3.4 / JDK 21 · MyBatis-Plus 3.5.7 · Sa-Token · 微信支付 V3（wxjava 4.6.0）· uni-app（Vue 3 + TypeScript）· Vue 3 + Vite + Naive UI（soybean-admin）· MySQL 8.0 · Redis / Redisson

**项目描述**
面向生鲜零售场景的全栈电商系统，包含 C 端微信小程序、PC 运营后台、后端服务三端。6 天内独立完成三端的设计与开发，覆盖商品、库存、购物车、订单、支付、退款、用户、运营后台等核心模块，提供约 84 个后端接口，实现从浏览下单到支付退款的完整交易闭环。

**核心职责与技术亮点**
- **全栈架构设计**：独立搭建「小程序 + PC 后台 + 后端」三端协同架构，后端统一提供 `/api/*` 接口，基于 Sa-Token 实现管理端 / C 端双 Token 鉴权，业务规则全部收敛于后端，前端仅做渲染，保证三端数据一致与可维护。
- **电商核心交易链路**：设计并实现商品、购物车、订单、支付、退款全链路；自研订单状态机（非连续状态值 0/1/2/4/3/9，按业务阶段排布），通过 `WHERE status = 来源态` 的原子判断实现状态流转，避免范围比较、天然保证转移幂等。
- **微信支付 V3 全链路对接**：基于 wxjava 4.6.0 实现 JSAPI 真实下单、微信异步回调验签、APIv3Key 报文解密与支付成功处理；将「真实回调 / 主动查单 / 演示支付」三条入口收敛到同一 `handlePaySuccess` 方法，复用库存扣减、订单状态变更、购物车精准清空逻辑，杜绝重复发货与状态错乱。
- **完整退款体系**：实现仅退款、部分退款、原路退回，按明细累计并做超额拦截；基于 Redisson 分布式锁防并发重复退款；定时任务支撑「商家超 24h 未处理自动同意退款」「待收货超 12h 自动确认收货」等自动化时效。
- **并发与一致性保障**：订单表引入乐观锁（`version` 列）防止支付回调与后台改单的并发丢失更新；支付成功与库存 / 购物车变更置于同一数据库事务，清空失败则整体回滚、由微信重试回调补齐，保证最终一致。
- **数据安全与工程规范**：密钥（微信支付 APIv3Key、COS SecretKey 等）以 AES 密文存储于 `sys_config` 配置表、证书落非公开目录、yml 仅保留占位符，**全程不进代码仓库**；沉淀数据库结构漂移修复、运维部署、商用运维等系列文档，建立「先改文档再改代码」的一致性约定。
- **可演示的工程化设计**：针对小程序个人主体暂无法开通真实商户号的约束，设计「模拟支付开关」——以与真实回调完全一致的业务逻辑完成完整交易链路演示，资质齐备后仅填配置即可切换真实收款，体现生产级工程判断力。

**关键词**：全栈开发 · Spring Boot · 微信小程序 · uni-app · 微信支付 V3 · 订单状态机 · 分布式锁 · 幂等设计 · 退款体系 · MySQL · 高并发一致性 · 数据安全
