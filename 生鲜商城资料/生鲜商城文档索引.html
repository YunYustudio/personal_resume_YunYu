〇、项目简介

一套面向生鲜（果蔬 / 肉禽 / 水产 / 日配）零售场景的全栈电商系统：

  • C 端微信小程序（uni_free_mall）：商品浏览、购物车、下单、支付、订单跟踪、售后退款、个人中心。
  • PC 运营后台（soybean-admin）：商品 / 订单 / 店铺配置 / 内容 Banner / 服务保障 / 数据大屏。
  • 后端服务（Mall_YunYu）：统一 API、鉴权、支付与退款、定时任务、系统配置。

⚠️ 安全红线：任何真实密钥（微信支付 APIv3Key / appSecret、COS SecretKey、商户号等）一律不进提交的配置文件、不进 Gitee；密钥存 sys_config 表（AES 密文），yml 仅保留 ${...:} 占位兜底。

四、关键设计决策 已拍板，勿随意改

  1. 模拟支付开关 = sys_config.pay_demo_enabled 专用列；开=1 走演示分支，关=0 走真实链路，与 wxpay_enabled 互斥。
  2. 密钥安全：APIv3Key / COS SecretKey 库内 AES 密文，yml 只放 ${...:} 占位，不入库文件、不提交 Gitee。
  3. 个人主体约束：微信小程序为个人主体，真实微信支付不可开通；真收款须先办个体户执照升级主体。
  4. 购物车清空时机：在「支付成功」时按 order_info.source_cart_ids 精准清空对应条目（非下单时）。
  1. 订单乐观锁：order_info.version 列防支付回调与后台改单并发丢失更新。
  2. 自动时效（写死常量，保持简单）：待收货 12h 自动确认；已完成 24h 内可申请售后；待发货用户退款商家 >24h 自动同意。
  3. 退款语义边界：「取消订单」= 已支付未发货用户主动退单原路退款；「申请退款/售后」= 待收货/已完成时发起，走不同入口。
