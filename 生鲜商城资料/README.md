## 〇、项目简介

**生鲜商城小程序**是一套面向生鲜（果蔬 / 肉禽 / 水产 / 日配）零售场景的全栈电商系统，包含：

- **C 端微信小程序**（`uni_free_mall`）：商品浏览、购物车、下单、支付、订单跟踪、售后退款、个人中心。
- **PC 运营后台**（`soybean-admin`）：商品 / 订单 / 店铺配置 / 内容 Banner / 服务保障 / 数据大屏。
- **后端服务**（`Mall_YunYu`）：统一 API、鉴权、支付与退款、定时任务、系统配置。

当前定位为**个人主体 · 体验/演示版**：小程序以个人开发者身份发布体验版给客户演示，**真实微信支付需先办理个体工商户营业执照 → 升级主体 → 申请微信支付商户号**后方可开通（详见 04 / 13 目录）。演示阶段通过后端「模拟支付开关」完成完整交易链路演示，不调真实微信支付。

> ⚠️ **安全红线**：任何真实密钥（微信支付 `APIv3Key` / `appSecret`、COS `SecretKey`、商户号等）**一律不进提交的配置文件、不进 Gitee**。密钥存 `sys_config` 表（AES 密文），yml 仅保留 `${...:}` 占位兜底。

## 七、关键设计决策（已拍板，勿随意改）

1. **模拟支付开关 = `sys_config.pay_demo_enabled` 专用列**（全局控制，非 JSON、非 ext_config）：
   - 开=1 时 `/api/pay/create` 走演示分支（复用支付成功逻辑、`transaction_id` 写 `MOCK_` 前缀），不调真实微信；关=0（默认）走真实链路。
   - 与 `wxpay_enabled` 互斥；演示单用 `MOCK_<orderNo>` 前缀标识，演示后跑 [演示模式_清理SQL.sql](04_支付与交易/演示模式_清理SQL.sql) 定向删除，绝不 TRUNCATE。
   - 表结构仅 `sys_config` 加 1 列，业务表零改动；已有库用 [sys_config_pay_demo字段补齐.sql](09_系统配置/sys_config_pay_demo字段补齐.sql) 幂等补齐。
2. **密钥安全**：微信支付 APIv3Key / COS SecretKey 库内 AES 密文存储，yml 只放 `${...:}` 占位兜底，真实密钥不入库文件、不提交 Gitee。
3. **个人主体约束**：微信小程序为个人主体，**真实微信支付不可开通**；演示靠 §8.3 的模拟支付开关，真收款须先办个体户执照升级主体。
4. **购物车清空时机**：在「支付成功」时按 `order_info.source_cart_ids` 精准清空对应购物车条目（非下单时），避免未付款/超时取消误删。见 [order_info_source_cart_ids.sql](11_数据库修复脚本/order_info_source_cart_ids.sql)。
5. **订单乐观锁**：`order_info.version` 列防「支付回调」与「后台改单」并发丢失更新。见 [order_info_version乐观锁.sql](11_数据库修复脚本/order_info_version乐观锁.sql)。
6. **自动时效（写死常量，保持简单）**：
   - 待收货 12h 未确认 → 系统自动确认收货（定时任务 `AutoConfirmReceiveTask`，锚点 `deliveryTime`）。
   - 已完成订单仅确认收货后 24h 内可申请售后（锚点 `receiveTime`），超时按钮隐藏 + 后端 `apply()` 拦截。
   - 待发货用户发起的自动同意退款：商家 >24h 不处理 → 定时任务 `RefundAutoAgreeTask` 自动同意。

## 八、数据库修复脚本说明（11 目录）

活库发生过**结构漂移**：多张表的 `id` 列丢失 `AUTO_INCREMENT`（建表 DDL 有，库里被改过），导致 INSERT 报 `Field 'id' doesn't have a default value`。已逐个修复的表：`user_address` / `order_info` / `order_item` / `cart` / `user_favorite`。

11 目录收纳全部修复脚本：

| 脚本 | 作用 | 用法 |
|------|------|------|
| 全库_id自增补齐.sql | **一次性根治**：SELECT 出当前库所有「id 是主键、整型、但未自增」表的 ALTER 语句 | Navicat 选中业务库执行该 SELECT，复制结果列 `_sql` 再执行 |
| order_info_id自增修复.sql | 单表修复 `order_info.id` 自增 | 独立执行 |
| cart_id自增修复.sql | 单表修复 `cart.id` 自增（修"加购物车报错"） | 独立执行 |
| user_address_id自增修复.sql | 单表修复 `user_address.id` 自增 | 独立执行 |
| order_info_source_cart_ids.sql | `order_info` 新增 `source_cart_ids` 列（支付成功精准清空购物车） | 独立执行 |
| order_info_version乐观锁.sql | `order_info` 新增 `version` 乐观锁列 | 独立执行 |

> ⚠️ **首推用《全库_id自增补齐.sql》一次性修完所有漂移表**，再单独跑 `source_cart_ids` / `version` 两个结构新增脚本。所有脚本均幂等、不动数据。

## 十、文档与代码一致性约定
